# 第一课预习：从安装到第一个 PR

跟着做完，你会得到：

- 一个能跑的 MySQL 8.0 + Navicat；
- 一张有 5 行数据的练习表；
- 会写增、改、删、批量增和条件查询；
- 一个通过自动评测的 Pull Request。

预计 60–75 分钟。卡住了先看 [常见错误](#6-常见错误)。

## 1. 安装 MySQL 8.0

这一节只给检查清单，不展开安装细节。

1. 打开 MySQL 官方下载页，下载 **MySQL Installer for Windows**。
2. 安装类型选 **Server only** 即可。
3. 配置时注意三件事：
   - 端口用默认的 `3306`；
   - 设置并记住 `root` 密码；
   - 勾选把 MySQL 注册为 Windows 服务。
4. 安装完成后，打开 Navicat 或命令行，执行：

```sql
SELECT VERSION();
```

看到 `8.0.x` 就说明装好了。

> 已经装过 MySQL 8.0 的同学跳过这一节。

## 2. 安装 Navicat（可选）

Navicat 只是图形客户端，不是数据库本身。

1. 安装 Navicat（16 或 17 都可以）。
2. 新建连接：
   - Host：`localhost`
   - Port：`3306`
   - User：`root`
   - Password：安装 MySQL 时设置的密码
3. 点“测试连接”，通过后保存。

没有 Navicat 授权也没关系，用下面任意一个：

- DBeaver（免费）
- MySQL Workbench（免费）
- 命令行 `mysql`

SQL 完全一样，不需要为了预习买 Navicat。

## 3. 建练习库，执行 init.sql

1. 在 Navicat 里右键连接，选择“新建数据库”。
2. 数据库名填 `preview`，字符集选 `utf8mb4`。
3. 打开仓库里的 `preview/init.sql`。
4. 把整个文件复制到查询窗口，点执行。
5. 执行下面这条，确认有 5 行数据：

```sql
SELECT * FROM members;
```

`init.sql` 可以重复执行。**改坏了就整段重跑一次**，数据会回到 5 行。

## 4. 增、改、删、批量增

### 4.1 新增一条

打开 `preview/01_insert.sql`：

```sql
INSERT INTO members (name, class_name, major, score)
VALUES ('孙八', '2025-1', '计算机', 90);

SELECT * FROM members;
```

执行后，表里会多一行“孙八”。

### 4.2 修改一条

打开 `preview/02_update.sql`：

```sql
-- 先查，确认改的是谁
SELECT id, name, score FROM members WHERE id = 1;

-- 再改
UPDATE members SET score = 80 WHERE id = 1;

-- 再查，确认改对了
SELECT id, name, score FROM members WHERE id = 1;
```

**重点**：`UPDATE` 一定要带 `WHERE`。

```sql
-- 不要执行！这会把所有人的分数改成 0
UPDATE members SET score = 0;
```

### 4.3 删除一条

打开 `preview/03_delete.sql`：

```sql
SELECT id, name FROM members WHERE id = 4;

DELETE FROM members WHERE id = 4;

SELECT id, name FROM members WHERE id = 4;
```

**重点**：`DELETE` 也要带 `WHERE`，否则会删掉整张表的数据。

### 4.4 批量新增

打开 `preview/04_batch_insert.sql`：

```sql
INSERT INTO members (name, class_name, major, score) VALUES
('周九', '2023-3', '数学', 70),
('吴十', '2024-3', '英语', 60),
('郑十一', '2022-2', '计算机', 95);

SELECT * FROM members;
```

四条演示都跑完后，表里应该有 8 行：

```text
5 行初始数据 + 1 行新增 - 1 行删除 + 3 行批量新增 = 8 行
```

如果数字不对，重跑 `preview/init.sql`，再按顺序跑一遍。

## 5. 条件查询

打开 `preview/05_select.sql`，一条一条执行。

```sql
-- 全部
SELECT id, name, score FROM members;

-- 比较
SELECT id, name, score FROM members WHERE score >= 85;

-- 字符串
SELECT id, name, major FROM members WHERE major = '计算机';

-- 模糊
SELECT id, name FROM members WHERE name LIKE '张%';

-- 范围
SELECT id, name, score FROM members WHERE score BETWEEN 80 AND 90;

-- 多选
SELECT id, name, major FROM members WHERE major IN ('计算机', '数学');

-- 组合
SELECT id, name, score FROM members
WHERE major = '计算机' AND score >= 85;

-- 排序 + 截断
SELECT id, name, score FROM members
ORDER BY score DESC, name ASC
LIMIT 3;

-- 计数
SELECT COUNT(*) AS cnt FROM members;

-- 分组
SELECT major, COUNT(*) AS cnt FROM members GROUP BY major;
```

练习方法：每条先照抄跑通，然后改一个条件再跑。

- 把 `>= 85` 改成 `>= 90`；
- 把 `'计算机'` 改成 `'数学'`；
- 把 `LIMIT 3` 改成 `LIMIT 2`；
- 把 `'张%'` 改成 `'%三'`。

## 6. 常见错误

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `You have an error in your SQL syntax` | 用了中文引号 `‘` `’`，或者漏了分号 | 全部换成英文引号 `'`，每条语句末尾加 `;` |
| `Unknown column 'xxx'` | 列名拼错，或者用了中文列名 | 对照 `init.sql` 里的列名 |
| `No database selected` | Navicat 没有选中数据库 | 双击 `preview` 数据库，再开查询窗口 |
| `Data too long for column` | 字符串超过 `VARCHAR` 长度 | 缩短内容，或改表结构 |
| 查询结果多出很多重复行 | 演示脚本重复执行了 | 重跑 `preview/init.sql` |
| 所有人的分数都被改了 | `UPDATE` 忘了写 `WHERE` | 重跑 `preview/init.sql`，重新来 |
| 整张表空了 | `DELETE` 忘了写 `WHERE` | 重跑 `preview/init.sql`，重新来 |

三条保命习惯：

1. `UPDATE` / `DELETE` 之前，先用同样的 `WHERE` 跑一次 `SELECT`。
2. `UPDATE` / `DELETE` 必须带 `WHERE`。
3. 改坏了就重跑 `preview/init.sql`，不要手工修数据。

## 8. 提交 PR

### 8.1 Fork 仓库

打开课程仓库页面，点右上角 **Fork**，复制到你自己的 GitHub 账号下。

### 8.2 Clone 到本地

```bash
git clone https://github.com/<your-github-username>/db-preview.git
cd db-preview
git remote add upstream https://github.com/<upstream-owner>/db-preview.git
```

把 `<your-github-username>` 换成你的 GitHub 用户名，把 `<upstream-owner>` 换成老师给的仓库所有者。

### 8.3 建分支

```bash
git fetch upstream
git switch -c hw01/<your-github-username> upstream/main
```

### 8.4 复制模板并完成作业

Git Bash / macOS / Linux：

```bash
mkdir -p submissions/<your-github-username>/hw01
cp homework/hw01/templates/* submissions/<your-github-username>/hw01/
```

Windows PowerShell：

```powershell
New-Item -ItemType Directory -Force submissions\<your-github-username>\hw01
Copy-Item homework\hw01\templates\* submissions\<your-github-username>\hw01\
```

然后在编辑器或 Navicat 里完成：

- `01_dml.sql`：四条增删改语句；
- `02_q1_score.sql` 到 `05_q4_top3.sql`：四条查询；
- `README.md`：GitHub 用户名和三个回答。

### 8.5 提交并推送

```bash
git add submissions/<your-github-username>/hw01
git commit -m "hw01: <your-github-username>"
git push -u origin hw01/<your-github-username>
```

### 8.6 开 Pull Request

回到 GitHub 上你自己的 fork，点 **Compare & pull request**。

- base 仓库：老师的仓库
- base 分支：`main`
- head 分支：`hw01/<your-github-username>`
- 标题：`[HW01] <your-github-username>`

提交 PR 后，等 `autograde` 变绿。

- 第一次提交 PR 可能显示 **Pending approval**，这是正常的，等老师批准；
- 红色就点 `Details`，按提示改；
- 改完在同一个分支继续 `commit + push`，不要关 PR 重开；
- 绿色后等老师合并，不要自己 merge。

### 8.7 不要做的事

- 不要改 `preview/`、`homework/`、`grader/`、`.github/`；
- 不要改别人的 `submissions/` 目录；
- 不要提交 zip、`.idea`、`node_modules`；
- 不要直接在 GitHub 网页上改完就 merge 到自己的 `main` 再开 PR，分支要从 `upstream/main` 开。

## 10. 常见问题

### Q1：`autograde` 一直 Pending 怎么办？

第一次向仓库提交 PR，GitHub 需要维护者批准 workflow。等老师点一下即可，不用重复提交。

### Q2：`autograde` 红了，但不知道错在哪？

点 check 旁边的 `Details`，看 `Summary` 里的表格。每一项都会写期望值和实际值。

### Q3：我本地跑出来是对的，为什么评测不对？

评测会重置数据库，并使用另一份数据跑查询。检查：

- 查询里有没有写死姓名或分数；
- 有没有漏 `ORDER BY`；
- 列名、列顺序是否和题目一致；
- 有没有多写 `SELECT *`。

### Q4：没有 Navicat 怎么办？

用 DBeaver、MySQL Workbench 或命令行 `mysql`，SQL 完全一样。

### Q5：MySQL 装的是 5.7，可以吗？

最好装 8.0。课程里的函数索引、`utf8mb4` 默认排序规则等都以 8.0 为准。

### Q6：中文显示成乱码？

把 SQL 文件保存为 UTF-8，Navicat 连接字符集设为 `utf8mb4`，数据库也用 `utf8mb4`。

### Q7：可以只交 SQL，不写 README 吗？

不可以。README 占 10 分，也用来确认 GitHub 用户名。

### Q8：可以改 `preview/init.sql` 方便自己练习吗？

本地可以，但**不要提交到 PR**。PR 里只允许改 `submissions/<你的 GitHub 用户名>/hw01/` 下的文件。
